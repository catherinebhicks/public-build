## The angle

Sixty-six sections of behaviour, and no way to tell when any one of them is
satisfied. This is the layer that turns the documents into a backlog.

## Waiting on

- PRD §65 — Acceptance criteria (TBD)

## What the source sections say so far

Covers testable criteria for each behavioural section, so it is possible to
tell when a section is satisfied.

The convention is already chosen: given / when / then, a handful per
behaviour, written against the behaviour rather than the implementation.

§33 defines product-level success. §65 is the per-feature layer beneath it,
and the spec says it is what converts these documents into a buildable
backlog.

## Questions this post would have to answer

- How do you write given/when/then for a behaviour whose correctness is a
  judgement call, like whether a probe was warranted?
- Which criteria are automatable and which need the human review from the
  evaluation programme?
- Does every section get criteria, or only the behavioural ones — and who
  decides which is which?
